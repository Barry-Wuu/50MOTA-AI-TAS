# 50F 真·通关链（08 Java 版源码实证）

> 写于 2026-11-11。全部结论来自 `08_Java_MTower08a/decompiled/MTower.java` 的 `eventMT` / `ending` /
> `Zeno2` 函数，坐标已用 `magic_tower1_map_50f.json` 的 terrain 交叉核对（24F 动态地形逐格吻合）。
> **本文件修正 `MAP_NOTES.md` §4 的一条错误**：那里写「49F(6,3)→50F(6,5)（UP_PATCH）」，
> 实际 50F 入口是 **24F(6,0)**（假公主剧情传送），落点 **50F(6,7)**。

## 0. 坐标口径（已二次确认）

- `map[row][col]` / `mapObject[row][col]`；`row=band*13+y`、`col=slot*13+x`；**层号 = band*10 + slot + 1**。
- 地形 `mapAttribute[idx][16]` = 全局**列**，`[17]` = 全局**行**（`landing_table.json` 的 `_meta` 同口径）。
- 佐证：24F 初始 `map[26][45]=31; map[27][44]=1; map[27][46]=1; map[28..30][45]=3`（loadMapData，行 14094-14099）
  与 JSON 里 24F terrain 的 (6,0)=31 / (5,1)(7,1)=1 / (6,2..4)=3 **逐格相同**。

## 1. 完整链条（按执行顺序）

- (6,5) 是小偷/魔王格，(6,7) 是落点与全部对话触发格，两者相距 2 格、同一房间内。

## 2. 第二条入口：41F(6,5) 的地形码 108

- `mapAttribute[108][3]=2`（type 2 跳转），`[1]=34`（上行梯图素），`[16]=123 / [17]=59` ⇒ **落点 50F(6,7)**。
- 唯一放置点：行 1930 `mapObject[57][6] = 108` ⇒ **41F(6,5)**。
- 放置条件（行 1901-1933）：`mapObject[68][125]==1` 且 `mapObject[54][2]==0` 且 `mapObject[54][10]==0`
  ⇒ 41F(2,2) 与 41F(10,2) 两只魔術師都死了（`mapObject[68][125]` 由 41F(10,2) 的门动画置 1，行 13751-13754）。
  同时把 41F(5,6)(6,6)(7,6) 三格蓝门改成墙、(5,7)(7,7) 两墙改成地板，再在 (6,5) 放 108。
- 结论：41F 是**备用/回程入口**；剧情主线入口是 24F。

## 3. 最终战数值（决定路线顺序）

- obj57 初始：HP 8000 / ATK 5000 / DEF 1000 / GOLD 500（行 11443-11454）。
- 行 1745：**49F 的 8 只 obj58 魔法警卫全灭**且 Zeno 仍在 (6,3) ⇒ `objectAttribute[57][10/11/12] = 800/500/100`。
  这是**全局改写**，50F 的 Zeno2 沿用同一行数据 ⇒ 最终战就是 **800/500/100**。
- 因此顺序必须是：**先 49F 清 8 警卫（把魔王削到 800/500/100）→ 再走 24F 秘道**。
  若先走 24F，最终战是 8000/5000/1000，且 `ending()` 已把 24F 通道还原（一次性），
  回头只能靠 41F(6,5) 那条备用入口（需先杀 41F 两只魔術師）。

## 4. 对现有路线脚本的影响

- `z2_route.py` 目前止于 V77（47F），尚未建模 48F/49F/26F/24F/50F。
- `landing_table.json` 的 `floors["49"].event_up` 写的是 `trigger (6,3) → dest 50F(6,5)`，**应改为**：
  50F 入口 = 24F(6,0)（`ending()` 传送），落点 50F(6,7)；41F(6,5) 为地形码 108 备用入口，落点同为 (6,7)。
- 50F 段可建模为：传送落 (6,7) → 原地 11 页对话（计数 0→12）→ 走到 (6,5) 开打 → 结算。
