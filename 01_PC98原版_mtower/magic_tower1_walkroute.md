## 终局（隐藏层 · 时空之门）

2. 对应“不存在楼层”的门使用 → 传送到大表第 6 带隐藏层（结局层）
3. 该层中央：**龍(3×3 大图块)** + **魔導師ゼノ 并肩**（剧情：真凶是龙，芝诺与勇者和解共斗）

## 附：00 层（隐藏层）通达方式（源码级证据）

`MTower.class` 的 `eventMT` 用 `mapY*10 + mapX + 1` 表示当前楼层序号（mapX=槽位、mapY=带），并在两处硬编码特例：

| 偏移 | 条件 | 行为 |
|---|---|---|
| 4700 | `index == 1` | `mapX=1; mapY=5` → 切到 block 52，即 00 层 |
| 3988 | `index == 52` | `mapX=0; mapY=0` → 回到 1F |

其余楼层一律按 `index±1` 前进/后退，跨带时 `mapX±9 / mapY∓1`。00 层的楼梯位于 (1,1)，与 1F 的门格 (1,1) 同位（两格地形均为 crop 34 / 文本 139）。因此：

- 与 00 层配对的**只有 1F**；23F 的 "GO 0F" 只是提示；48F(1,1) 与目录区 (4,3) 的单个 obj115 判为残留格，与 0F 事件无关（此处更正我先前版本的推测）。
- obj115：`type=OBJECT_DOOR(5)`，但 `item/number/jump_x/jump_y` 全为 0 且 `crop=32`（地板图素），故不可见、不传送。

## 附：隐藏物体（事件后才出现的掉落/道具）

这些格在初始地图上多半是空格、墙、甚至已被怪物占据，
是引擎在事件分支里用 `mapObject[行][列]=ID` 写进去的（提取脚本见 `_dynamic_spawns.source`）。
渲染方式：同一格的多个对象**全部叠画**——第 1 个对象以 55% 不透明度铺满整格（主对象，如战后出现的水晶/药水/钥匙），第 2~4 个以 72% 不透明度、24px 贴在右下角/左下/右上/左上，第 5 个起在格下放数字贴片表示剩余数量；静态物体仍在底层照常绘制。这样"先出现怪、打掉后原地掉宝"的两层状态在同一格里都看得见。

覆盖 22 层、115 格；完整清单见 `magic_tower1_dynamic.csv` 与每层 JSON 的 `dynamic_objects`。
