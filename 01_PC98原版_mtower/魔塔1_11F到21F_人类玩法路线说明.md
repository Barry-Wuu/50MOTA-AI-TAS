## 一、为什么放弃 A*，改用"人类玩法"

原先 `build20.py` 用 A* 做**跨层全局搜索**，结果有两个致命问题：

| 问题 | 表现 |
|---|---|
| 楼层反复横跳 | 产物在 12F→19F 之间来回乱窜（17F→18F→17F→16F→18F→19F→17F…），因为已清空楼层里"最短路"可以任意绕 |
| 跨层状态爆炸 | 一次性规划"12F→18F"展开 30 万状态仍不可达；BOSS 区被怪群包围时展开 80 万直接超时 |

`play20.py` 的做法完全不同，也更接近真人爬塔：

| 原则 | 具体做法 |
|---|---|
| **路线 100% 人工** | 每层去哪几个格子、按什么顺序，写死在 `SEGS` 字典里，算法不参与决策 |
| **导航用 BFS 而非 A*** | 自研队列式 BFS，无启发式、无代价加权，只做"从这个格子走到那个格子的最短路" |
| **逐层推进** | 上/下楼一次只规划一层（`ascend` / `descend`），人类就是一层一层爬的，绝不跨 6 层全局规划 |

> BFS 在这里不是"搜索解法"，只是"走路"——它回答"从 A 格到 B 格怎么走最短"，
> 而"**该去哪、先拿什么**"完全由 `SEGS` 决定，这才是"人类玩法"的本质。

## 四、BOSS 战：吸血鬼バンパイア

引擎战斗公式（`mota_core.battle`）：

```
每击伤害 = ATK × 倍率 − 敌DEF        倍率：持十字架 obj103 → ×2
回合数   = ceil(敌HP / 每击伤害)
我方掉血 = (敌ATK − 我DEF) × (回合数 − 1)      ← 最后一回合敌人已死，不还手
```

代入 ATK115 / DEF57 / 十字架：

```
每击 = 115×2 − 66 = 164  →  回合 = ceil(444/164) = 3
掉血 = (199 − 57) × 2 = 284
```

实战：HP293 → 途经 `(6,8)` 吃到**动态写入的蓝药 +400** → 693 → 击杀掉 284 → **HP409**，安全通过。

> 献祭选的是**攻击**而非生命：把回合数从 5 压到 3，掉血从 560 降到 284。
> 要把回合压到 2 需要 ATK147（献 6 次、2440G），而手上只有 955G，做不到。

## 六、顺带修掉的两个引擎缺陷

### 1. 20F："进入"与"离开"是两套机制，原代码把它们绑反了

20F 的正确机制（Java 源码 `MTower.java:3080` 为证）：

```java
if (角色踏上 (6,8) 触发点 && (6,3)==obj20 && (6,9) 为空) {
    displayDoor(graphics, 123, 22, 4);   // 开门动画（(6,9)）
    mapObject[22][123] = 20;             // (6,9) → 可通行装饰
    banpaia(graphics);                   // 吸血鬼登场
    strNumber = 19;                      // 台词
}
```

| 阶段 | 机制 | 触发条件 |
|---|---|---|
| **进入** BOSS 间 | `(6,9)` 是**红门 obj27**，须持红钥匙开启——这才是"见 BOSS 的基本门槛"；踏入 BOSS 间后吸血鬼 obj59 登场于 `(6,6)`，`(6,8)` 为 +400 蓝药 | 红钥匙（此前误写"剧情自动开门、不耗红钥匙"，已更正） |
| **离开** BOSS 间 | 击败 `(6,6)` 吸血鬼后 `boss20=True`，`(20,6,1)` 才现出上行梯 | `boss20` |

原实现的错误有两层，都已修正：

1. **把"进入"绑到了 `boss20`**（死锁 bug）：旧代码要求"杀了 BOSS 才开 (6,9) 门"，而 BOSS 就在门后 `(6,6)`，形成死锁，BOSS 永远打不到。现改为 `(6,9)` 由 DOOR 分支要求**红钥匙**（见 BOSS 的门槛），`boss20` 只负责解锁 `(20,6,1)` 上行梯（离开机制）。

2. **曾误把红门当"剧情自动开门、不耗红钥匙"**（见上表旧描述）：这是错读了 Java `MTower.java:3080` 的 `displayDoor` 演出——那段是把门设为可通行装饰 obj20 并放出吸血鬼的**过场**，并非免钥开门。红钥匙这道门槛仍由 DOOR 分支把关，不可省（见本文开头"红钥匙门槛的澄清"）。

```python
if (f, nx, ny) == (20, 6, 9) and not self.boss20:   # 旧：死锁
    return ['blocked: 20F(6,9) 红门未开（需先击败吸血鬼）']
# 新：(6,9) 交给下方 DOOR 分支，无红钥匙→['无红钥匙，门 obj27 开不了']，有则消耗 1 把
```

> 吸血鬼 obj59 在本引擎中**进层即由 `FLOOR_WRITES[20]` 置于 `(6,6)`**（等价于原版踩 `(6,8)` 触发 `banpaia` 的登场效果），故进入 BOSS 间即可交战；`(6,8)` 同时是 +400 蓝药，正好是战前补血点。

### 2. 祭坛菜单选择无法从 CSV 复现

`altar_policy`（祭坛选生命力/攻击/防御）是引擎内部状态，而 CSV 只记录移动方向。
若脚本里设成 `'hp'`，回放时会回落到默认的 `'atk'`，导致**同一份 CSV 两次跑出不同结果**。

因此 `play20.py` 刻意**不改** `altar_policy`，固定用默认 `'atk'`。
现已实测：脚本终态与 CSV 回放终态**逐项一致**（`21F(6,2) HP409 ATK115 DEF57 GOLD415`），路线可忠实复现。
